# 星采宣传片 · 验收标准（v1）

> 这份文件先于制作存在。它定义「优秀的产品宣传片」长什么样、雷区是什么，
> 以及本片在 3 个检查点分别要过哪些线。没写在这里的标准，不作为验收依据；
> 写在这里的标准，不达标就不算完成。

---

## 0. 一句话定义

**优秀的产品宣传片 = 用最少的认知成本，让目标观众在 30 秒内记住一句价值主张，并且相信它。**

三个关键词缺一不可：
- **记得住**：一句话主张，不是功能清单。
- **信得过**：用真实界面/真实数字当证据，不用装饰图凑数。
- **看得完**：节奏、卡点、信息密度匹配发布场景，不拖。

差的宣传片只有一个共同点：**信息很多，但记不住任何一句。** 它像一份被念出来的功能列表。

## 1. 评分维度（加权，总分 100，通过线 90）

| # | 维度 | 权重 | 满分表现 | 不及格表现 |
|---|---|---|---|---|
| A | 叙事/主张 | 25 | 前 3 秒抓到人，价值主张在第 2 个 beat 前落地，后面全是证据 | 开场讲公司/讲功能；看完记不住一句 |
| B | 真实可信 | 20 | 出现真实界面、真实数字、可核对的功能点 | 假 UI、编的数字、说了产品做不到的事 |
| C | 视觉设计 | 20 | 沿用品牌设计系统，层次 ≥3，两个视觉焦点，光底也有质感 | 纯色空白底、居中堆叠、AI 味配色 |
| D | 动效/节奏 | 15 | 有 build→breathe→resolve，缓动和时长有变化，卡点准 | 所有东西 `y:30+opacity` 同时进；转场都一样 |
| E | 声音/卡点 | 10 | BGM 与剪辑同拍，关键动作踩重拍，混音不糊 | 音乐只是随便垫着；卡点漂移 |
| F | 完成度/技术 | 10 | lint/check 全过、无溢出无黑帧、字幕对比达标、时长卡准 | 文字溢出、元素没出现、时长跑偏 |

**判定**：总分 ≥ 90 且**没有任何硬否决项**（见 §3）→ 通过。

## 2. 逐项：什么是好的，什么是差的

### A. 叙事与主张（最贵的一项）

**好**
- 开场 0–3 秒用**观众的语言**回答"我为什么要在乎"，不是产品内部词汇。
- 价值主张在**第 2 个 beat 之前**落地（reverse iceberg：先价值，后证据）。
- 结构是"痛点 → 反转 → 产品 → 证据 → CTA"，不是网页目录顺序。
- 每个镜头只干一件事，且这件事能追溯到那句主张。追溯不到的镜头直接砍。
- 结尾一句像人话的 CTA，而不是"了解更多"。

**差**
- 开场是 logo 动画、公司介绍、"本产品致力于……"。
- 把功能一条条念出来（feature tour / README 朗读）。
- 用了"赋能/闭环/一站式/智能化升级"这类空词。
- 镜头很多，但换一个镜头不影响理解 → 说明全是装饰。

**自检**：把所有"证据镜头"删掉，剩下的镜头还能独立说清价值吗？把"价值镜头"删掉，片子还成立吗？如果成立，说明它只是功能巡礼。

### B. 真实可信

**好**
- 用**真实产品的界面**当证据：真实截图/录屏、真实字段、真实数字。
- 数字只用在有分量的地方（对比、规模、结果），不用来当装饰。
- 说的每个能力都能在产品里点出来。
- 引用的品牌/图标只做识别性使用，不暗示官方背书。

**差**
- 用生成的假 UI 冒充产品界面。
- 编造用户量、增长率、评分。
- 拿"演示数据"说成真实客户成果（演示站必须标"演示数据"）。
- 界面模糊、被拉伸、比例失真、明显截断。

### C. 视觉设计

**好**
- 沿用产品既有的设计系统（星采 = 包豪斯纸品：米白底 + 炭黑描边 + 砖红强调 + 蓝/黄辅助，硬边、偏移阴影）。
- 每个画面至少 3 层：背景处理 / 主内容 / 前景装饰（分隔线、标签、数据条）。
- 每屏至少 2 个视觉焦点，眼睛有地方可以走。
- 内容锚定到边缘/分区，不做"居中悬浮"。
- 字号按视频尺度放大：标题 64–120px，正文 28–42px，标签 18–24px；不到 24px 的字要有理由。
- 浅色底也做得有质感（颗粒、网格、大字幽灵、硬描边），不是"空白幻灯片"。
- 一屏至少一个能把眼睛拉过去的强色，但同一个强调色贯穿全片。

**差**
- 纯黑/纯白底、无纹理、无装饰层 → "像没加载完"。
- 紫蓝渐变、青蓝霓虹、渐变文字、卡片左边一条彩色竖条 —— 典型 AI 设计味。
- 一屏六个同款卡片；所有东西等重居中。
- 网页尺寸直接搬进视频（14px 正文在视频里等于看不见）。
- 一屏换一套配色。

### D. 动效与节奏

**好**
- 每个场景走 build（入场，0–30%）→ breathe（有且仅有一个环境运动，30–70%）→ resolve（退场更快，70–100%）。
- 缓动有变化：全片同一段里不超过 2 个动效复用同一种 ease；入场用 `.out`，退场用 `.in`，位移用 `.inOut`。
- 时长有快慢对比：最慢镜头至少比最快镜头慢 3 倍。
- 入场方向有变化（左/右/缩放/纯淡入/字距），不是全部 `y:30`。
- 入场错峰按重要性排序，总错峰 < 500ms，入场之间相互重叠。
- 装饰元素有慢速环境运动（呼吸/漂移/脉冲），不是死的。
- 静止也是设计：高速之后留一拍静。

**差**
- 所有元素同一缓动、同一时长、同一方向同时入场。
- 装饰全静止；每个场景都套同一个环境缩放。
- 视频里的静止画面比运动画面多。
- 转场只有一种（全是交叉淡入）。

### E. 声音与卡点

**好**
- BGM 有真实鼓点、bass 走向和段落变化，不是"泛科技垫底音乐"。
- 剪辑对到节拍网格：转场、数字跳动、卡片砸入落在重拍或半拍上。
- 关键动作有音效，且在音效出现时音乐压一下（duck）。
- 混音干净：不爆音、不糊、人声（如有）清楚。

**差**
- 卡点靠肉眼对齐，漂 1–2 帧就能看出来。
- 音乐只是一直垫着，画面和它无关。
- 全程同一个音量，没有起伏。
- 音效糊在音乐里，或者根本没有。

**本片基准**：以实际曲目分析出的**真实脉冲**为准，不用理论值硬算。
当前 BGM（`assets/bgm-v3.mp3`）的真实脉冲 = **69.84 BPM**（1 拍 = 0.859s，1 小节 ≈ 3.436s），
网格见 `videos/stargather-promo/assets/beat-grid-v3.json`。历史值 123.05 / 92.29 BPM 均已弃用。

### F. 完成度与技术

**好**
- `npx hyperframes lint` 与 `npx hyperframes check` 全部通过。
- 无文字溢出、无元素未出现、无黑帧/白帧、无闪烁。
- 字幕/文字对比度满足 WCAG AA。
- 时长与目标一致（±2 秒内）。
- 分辨率/帧率/码率符合发布平台要求。
- 用一张关键帧接触表（contact sheet）通看全片，而不是只看几帧。

**差**
- 交付前没跑 lint/check，或跑了但忽略报错。
- 有元素因 `from()` 与并发 transform 冲突而从未出现（lint 查不出来）。
- 用了 iframe 嵌入实时网页导致渲染时冻结/空白。
- 只在某一帧看着没问题，全片有跳变。

## 3. 硬否决项（出现任意一条直接不通过，不论总分）

1. 出现产品做不到的功能 / 编造的客户或数据。
2. 用假 UI 冒充真实界面。
3. 泄露凭证、cookie、真实账号信息、内部 IP/域名/仓库名。
4. 使用未获授权或未署名（当许可证要求时）的素材/音乐。
5. 文字溢出画面、被截断、或被其他元素遮挡。
6. 全屏文字对比不达标，或存在无法阅读的帧。
7. 音乐来源不可追溯 / 版权不清。
8. 时长、画幅与交付要求不符。
9. 片中出现的第三方商标被用作自身品牌或暗示官方背书。

## 4. 本片特定验收（60s / 16:9 / 中文 / 横屏）

- **主张**：把收藏的视频，变成你自己的内容知识库。
- **结构**：PAS（痛点 → 加剧 → 解法 → 证据 → CTA）。
- **必须出现**：真实演示界面、真实数字（6 平台 / 40 命中 / 7 条可播视频 / 10 篇文章，取自演示快照）。
- **必须出现**：至少一处**真实视频真的在播放**（不是静态截图），以及可见光标 + 点击反馈。
- **品牌标志**：全片右上角固定**当前在用标志（M3「月碗托星」）**；不得使用已淘汰的第一轮概念稿。
- **标志版本**：最小使用尺寸须 ≥ 24px（M3 文档的简化版阈值）；本片用完整版，且不做透明/反白替换。
- **数字动画**：数量类数字用连续累加（proxy + `onUpdate`，逐帧插值 + `tabular-nums` + 固定宽度槽），
  不得用「每隔若干拍 set 一次」的跳字。
- **不出现**：任何真实凭证、真实账号、非演示数据被说成真实结果。
- **卡点**：69.84 BPM 真实脉冲网格（`assets/beat-grid-v3.json`）。
- **收尾**：品牌收束 + 一句 CTA。

> 注：本文件为 v1 版验收标准，"本片基准"与 §4 已按 v3 成片更新；§1–§3 的评分维度与硬否决保持不变。

## 5. 三个验收检查点

| 检查点 | 时机 | 要看什么 | 谁来判 |
|---|---|---|---|
| G1 分镜 | 动工写 HTML 前 | §1 的 A/B 两项：主张、结构、每镜头职责表 | 你看文字表 |
| G2 静帧 | 写好布局、渲染动效前 | §1 的 C 项：`storyboard.html` 关键帧版式与品牌一致 | 你开浏览器看 |
| G3 成片 | 渲染后 | §1 全部 + §3 硬否决 + 接触表通看 | 你 + 我按本文件逐项打分 |

G3 交付时附：`lint`/`check` 输出、接触表、逐项评分表（本文件 §1 的 A–F 打分）。

---

## 6. 判定

- **通过**：总分 ≥ 90，无硬否决，G1/G2/G3 三关都过。
- **有条件通过**：仅细节问题（如某处卡点偏 2 帧），列出待改清单。
- **不通过**：触发任一硬否决，或总分 < 90 —— 回到对应检查点重做，不掩饰。
