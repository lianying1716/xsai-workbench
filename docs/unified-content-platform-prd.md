# 统一内容抓取与视频分析平台需求文档（草案）

## 1. 背景与目标

当前工作区包含多个可复用项目：`MediaCrawler` 负责多平台内容抓取，`bili-sync` 可同步哔哩哔哩内容，`dysync.net` 具备抖音同步能力，`faster-whisper` 可做音视频转录，`wechat-article-exporter` 可作为前端管理经验参考。目标是将这些能力统一成一个平台：统一路由、统一前端、统一账号管理、统一任务调度、统一数据分析，并对外暴露为可调用的 skill/API。

## 2. 核心目标

1. 针对指定关键词定期抓取热门内容。
2. 支持抖音、哔哩哔哩账号登录与收藏夹/关注博主管理，并选择性拉取视频。
3. 对拉取视频进行转录、结构化文档生成与数据分析。
4. 提供外部 skill，使其他智能体或自动化流程可调用平台能力。
5. 提供统一前端管理模块，覆盖账号、数据看板、同步源、关键词任务、视频处理流水线。
6. 最终支持 Linux、macOS、Windows 单机部署使用。
7. 将现有 Git 项目的可复用能力抽离进自有项目结构，并为未来开源做许可证合规准备。

## 3. 用户角色

- 管理员：配置平台、管理账号、查看全局任务和系统状态。
- 内容运营：维护关键词、选择关注博主、查看热门内容和视频分析。
- 自动化调用方：通过 skill/API 发起抓取、同步、转录、查询和导出。

## 4. 范围

### 4.1 第一期必须实现

- 统一 Web 管理后台。
- 单管理员模式，不做多用户/多角色权限。
- Linux、macOS、Windows 单机可部署，不能绑定某个服务器环境。
- 抖音、哔哩哔哩账号接入状态管理，优先支持扫码或浏览器自动登录。
- 关键词抓取任务：关键词、平台、周期、热门排序、抓取数量、启停。
- 关注博主/收藏夹同步任务：账号、平台、来源、博主选择、同步周期。
- 视频资产库：来源、作者、标题、发布时间、保存目录、下载状态、转录状态、分析状态。
- 可配置内容保存根目录，支持本机目录或局域网 NAS 挂载目录。
- 转录流水线：下载视频或音频，调用本地 `faster-whisper` 生成文本。
- 基础分析：摘要、关键词、主题、互动数据、作者维度统计。
- 外部 skill/API：查询任务、创建任务、触发同步、查询视频、获取转录结果。

### 4.2 后续阶段

- 多平台扩展：小红书、知乎、微信公众号文章。
- 高级内容分析：趋势检测、竞品对比、爆款结构拆解、选题推荐。
- 多租户与团队权限。
- 内容导出：Markdown、JSON、CSV、知识库同步。

## 5. 系统模块

### 5.1 统一网关与路由

建议新增一个平台层服务作为统一入口，负责认证、权限、API 路由、任务编排和模块代理。各现有项目作为后端能力模块接入，不直接暴露给前端。

推荐新增 `platform-api`，采用 `Python + FastAPI` 作为统一后端主控层。理由是 `MediaCrawler` 和 `faster-whisper` 都在 Python 生态内，关键词抓取、转录、分析和后续 AI 处理更容易集成；FastAPI 自带接口文档，学习成本较低。`dysync.net` 和 `bili-sync` 先作为可调用服务模块，通过 HTTP、CLI 或适配器接入，避免一开始重写成熟逻辑。

推荐数据策略：数据库只保存任务、账号、元数据和状态；视频、音频、转录文档、分析文件不进入数据库。正式数据库采用 PostgreSQL，SQLite 仅用于本地开发或 Demo。

推荐路由示例：

- `/api/accounts/*`：账号与登录状态。
- `/api/crawl-tasks/*`：关键词抓取任务。
- `/api/sync-tasks/*`：收藏夹、关注博主、视频同步。
- `/api/assets/*`：视频、音频、文档资产。
- `/api/transcripts/*`：转录任务与文本。
- `/api/analytics/*`：数据看板与分析结果。
- `/api/skills/*`：外部 skill 调用入口。

### 5.2 抓取模块

基于 `MediaCrawler` 接入关键词抓取。任务配置包括平台、关键词、时间范围、排序策略、抓取上限、过滤规则、周期表达式。抓取结果进入统一内容表，视频类内容进入视频同步候选池。

### 5.3 账号与同步模块

基于 `dysync.net` 和 `bili-sync` 接入抖音、哔哩哔哩。账号模块需要保存平台、登录状态、Cookie/Token 有效期、最近检查时间、失效提醒。登录优先采用扫码或浏览器自动登录；平台限制自动登录时，提供 Cookie 手动导入。同步模块支持收藏夹同步、关注列表同步、指定博主同步和手动触发。

### 5.4 视频处理模块

视频进入资产库后执行统一流水线：

1. 元数据入库。
2. 按配置目录保存视频，必要时抽取音频。
3. 调用本地 `faster-whisper` 转录。
4. 在同一资产目录生成 Markdown/JSON 文档。
5. 执行分析任务。
6. 更新状态并展示在前端。

保存路径需要可配置，既支持本机路径，也支持 NAS 挂载路径，例如 `/mnt/nas/xsai-content`。推荐目录模板：

```text
{storage_root}/{platform}/{creator_name}/{publish_date}/{content_id}/
  video.mp4
  audio.wav
  transcript.md
  transcript.json
  analysis.json
  metadata.json
```

### 5.5 分析模块

首版分析指标包括播放、点赞、评论、收藏、转发、发布时间、作者、平台、关键词命中、转录摘要、主题标签。后续可加入趋势评分、内容质量评分和爆款因子。

### 5.6 外部 Skill/API

外部 skill 应以稳定 API 为核心，不直接调用内部项目。建议能力：

- `create_keyword_task`
- `list_keyword_tasks`
- `trigger_sync`
- `search_assets`
- `get_transcript`
- `get_analytics_summary`
- `export_asset_document`

所有 skill 调用必须带鉴权，并记录调用日志、参数、结果和耗时。

### 5.7 模块抽离与适配层

现有 Git 项目不能长期以原仓库拼接方式存在。平台应建立自有模块目录和统一接口，例如 `platform-api/modules/bilibili`、`platform-api/modules/douyin`、`platform-api/modules/transcription`、`platform-api/modules/crawlers`。第一阶段可以通过适配器调用现有项目；第二阶段逐步抽离核心能力；第三阶段删除对原仓库目录结构的依赖。

抽离原则：

- 先定义统一接口，再迁移实现，避免前端和调度层依赖具体项目。
- 能通过公开 API/CLI 调用的能力优先封装，不急于复制代码。
- 复制或改写代码前必须记录来源、许可证、改动点和归属模块。
- 对许可证不兼容的项目，只保留接口适配或重写实现，不直接合并代码。

许可证与授权策略：

- `bili-sync`、`faster-whisper`、`dysync.net` 为 MIT，适合复用但仍需保留版权声明。
- `yt-dlp` 为 Unlicense，可作为下载能力参考或依赖。
- `MediaCrawler` 标注为 `NON-COMMERCIAL LEARNING LICENSE 1.1`，授权已申请，可推进模块抽离；正式并入前必须归档授权凭据、允许范围、署名要求和再分发限制。
- `wechat-article-exporter` 使用 AG Grid Enterprise 相关配置，若复用前端代码需避免引入商业授权依赖。

### 5.8 跨平台单机部署

平台最终必须支持 Linux、macOS、Windows 单机部署。首选 Docker Compose 部署，同时保留本机开发启动方式。

跨平台要求：

- 路径统一通过配置项管理，不能硬编码 Linux 路径。
- NAS 保存目录由用户配置：Linux/macOS 可使用挂载路径，Windows 可使用盘符路径或 UNC 路径，例如 `Z:\xsai-content` 或 `\\NAS\xsai-content`。
- 本地 whisper、浏览器自动登录、视频下载、FFmpeg 等依赖需要启动前检测，并在前端显示诊断结果。
- 所有服务端任务必须能在单机离线局域网环境运行，除目标平台访问和可选大模型 API 外，不依赖云服务。
- 配置文件和数据目录需要区分，便于备份和迁移。

### 5.9 外部 API 与大模型配置

外部 skill 必须同时支持智能体调用和普通 HTTP API 客户端调用。前端工作台需要提供 Skill/API 配置页面，用于管理 API Key、启用状态、权限范围、调用限流、调用日志和示例请求。

内容分析首选外部大模型 API。前端工作台需要提供模型配置页面，用于配置供应商、Base URL、API Key、模型名、超时、重试、默认分析提示词和费用/调用量统计。本地模型可作为后续扩展，不作为第一期优先项。

## 6. 能力并入审查

原项目不保留独立运行能力，最终统一为平台模块。每个能力是否进入统一前端工作台，按“能否被配置、监控、追踪、导出”审查。

### 6.1 必须进入统一前端的能力

- `MediaCrawler`：平台账号状态、关键词任务、搜索平台选择、抓取周期、抓取结果、异常日志、代理配置。
- `dysync.net`：抖音账号登录、关注列表、收藏/合集来源、博主选择、视频同步任务、同步历史。
- `bili-sync`：哔哩哔哩账号登录、收藏夹、合集/投稿来源、UP 主选择、视频同步任务、同步历史。
- `faster-whisper`：模型选择、设备/计算类型、转录队列、转录进度、失败重试、转录结果查看。
- `yt-dlp` 或下载能力：下载队列、下载状态、文件路径、失败原因、重试操作。
- 统一分析能力：外部模型 API 配置、分析任务、摘要/标签/评分结果、调用日志。
- 统一存储能力：NAS/本地目录配置、目录可用性检测、容量提示、资产文件定位。

### 6.2 不直接进入前端的能力

- 原项目的独立配置文件、独立 Web UI、独立 CLI 参数不暴露给最终用户。
- 仅供内部适配使用的字段保留在后端模块配置中，通过统一设置页抽象为可理解选项。

## 7. 统一前端信息架构

前端应是管理工作台，而不是营销页。建议导航：

- 总览：系统状态、今日抓取量、待处理视频、账号异常、热门趋势。
- 账号管理：抖音、哔哩哔哩账号登录状态、Cookie 更新、失效提醒。
- 关键词抓取：任务列表、任务编辑、抓取记录、结果筛选。
- 关注与收藏同步：账号来源、关注博主选择、收藏夹选择、同步历史。
- 视频资产库：视频列表、保存位置、状态筛选、转录文本、分析结果、导出。
- 数据分析：平台、作者、关键词、时间维度看板。
- Skill/API：接口密钥、启用状态、权限范围、调用日志、示例请求。
- 模型配置：外部 API 供应商、Base URL、API Key、模型名、调用量、默认分析提示词。
- 系统设置：管理员账号、存储目录、Docker 部署、调度、并发、代理、模型与转录配置。

## 8. 初步数据对象

- `Account`：平台、账号标识、昵称、凭证状态、过期时间。
- `Creator`：平台、作者 ID、昵称、主页、是否同步。
- `CrawlTask`：平台、关键词、周期、状态、过滤条件。
- `SyncTask`：平台、账号、来源类型、目标作者/收藏夹、周期。
- `ContentItem`：平台、标题、作者、URL、指标、抓取来源。
- `MediaAsset`：内容 ID、保存根目录、文件路径、下载状态、转录状态、分析状态。
- `Transcript`：资产 ID、语言、分段文本、全文、模型版本。
- `AnalysisResult`：资产 ID、摘要、标签、指标快照、评分。
- `SkillCallLog`：调用方、工具名、参数摘要、状态、耗时。
- `ModelProvider`：供应商、Base URL、模型名、鉴权状态、默认启用状态。

## 9. 非功能需求

- 调度可靠：任务失败可重试，状态可追踪。
- 模块隔离：单个抓取模块失败不影响平台整体。
- 凭证安全：Cookie/Token 加密存储，前端不展示完整敏感信息。
- 存储可控：所有抓取内容、视频、音频、转录和分析文件必须能指定保存目录。
- 跨平台：Linux、macOS、Windows 单机环境都必须可部署、可配置、可诊断。
- 开源合规：所有抽离代码必须保留来源和许可证记录，不合规模块需替换或重写。
- 可观测性：统一日志、任务耗时、失败原因、队列长度。
- 可扩展性：新增平台时不改前端主结构，只新增平台适配器。

- 新增统一网关/API。
- 新增统一前端导航与基础页面。
- 接入账号状态、任务列表、资产库的最小数据模型。
- 建立自有模块目录、适配器接口和跨平台配置体系。
- 建立 PostgreSQL 元数据模型、Docker Compose 编排和 NAS 路径诊断。

## 12. 已确认决策

- 后端主控层推荐采用 `Python + FastAPI`，现有项目作为后端能力模块接入。
- 权限第一期采用单管理员模式。
- 登录优先采用扫码或浏览器自动登录，Cookie 手动录入作为兜底。
- 视频、音频、转录和分析文件采用本地文件系统保存，可指向 NAS 挂载目录。
- 转录采用本地 `faster-whisper`。
- 最终必须支持 Linux、macOS、Windows 单机部署。
- 现有 Git 项目能力需要逐步抽离进自有项目结构，并以未来开源为前提做许可证合规。
- 正式数据库采用 PostgreSQL。
- 首选 Docker Compose 作为部署方式。
- 内容分析首选外部大模型 API。
- 外部 skill/API 必须在前端工作台提供配置与调用日志。
- 原项目不保留独立运行能力，必须审查并并入统一前端工作台。
